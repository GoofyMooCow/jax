Toolchain & versions

How Jax keeps a project building the same way on every machine, for years.

Two pieces

PieceWhat it is
Launcher (jax)A tiny static program you install once. It reads the project's manifest, makes sure the right toolchain is present, and runs it. It never changes how your code is built.
ToolchainOne directory per Jax version containing the compiler/CLI (bin/jax-driver) and the runtime stubs used for executables. Immutable once installed.

Which version runs?

The launcher picks the first match:

  1. jax +0.1.0 build: an explicit selector
  2. the JAX_TOOLCHAIN environment variable
  3. the jax = "..." pin in the nearest jax.toml (the normal case)
  4. a //! jax 0.1.0 comment in the first lines of a single .jax file
  5. your default toolchain, else the newest installed, else the newest available

If the chosen version is missing it is downloaded, its SHA-256 is verified against the release manifest, and it is unpacked and moved into place atomically, so an interrupted download never leaves a half-installed toolchain. Concurrent runs coordinate with a lock.

Managing toolchains

jax toolchain list              # installed versions (* = default)
jax toolchain install 0.1.0     # add --set-default to make it the default
jax toolchain remove 0.1.0
jax toolchain default 0.1.0
jax toolchain which             # the driver that would run here
jax toolchain latest            # newest version the server offers
jax toolchain prune [--yes]     # remove versions nothing needs (dry run without --yes)

Where things live

~/.jax/                       # %LOCALAPPDATA%\Jax on Windows; override with JAX_HOME
  bin/jax                     # the launcher
  toolchains/0.1.0/           # one folder per version
    bin/jax-driver
    runtimes/linux-x64/jax-rt
  config.toml                 # preferences; never affects build output
  tmp/  locks/                # scratch space

Environment variables

VariableMeaning
JAX_HOMEWhere Jax keeps toolchains and config
JAX_DIST_URLWhere toolchains are downloaded from (https://, or file:// for a local folder)
JAX_OFFLINE=1Never touch the network; fail with a clear message if something is missing
JAX_TOOLCHAINForce a toolchain version
JAX_VERBOSE=1Say which toolchain was chosen and why

Hosting your own mirror

Distribution is just static files. Any web server, object store or shared folder works:

latest.txt
toolchains/0.1.0/manifest.toml                          # sha256 for every platform
toolchains/0.1.0/jax-toolchain-0.1.0-linux-x64.tar
bin/linux-x64/jax   and   jax.sha256                    # the launcher, used by the installers

Point JAX_DIST_URL (or dist_url in config.toml) at it. The default is https://goofymoocow.github.io/jax/dist. For an air-gapped machine, copy a dist folder over and use a file:// URL together with JAX_OFFLINE=1.

Releases are permanent

Published toolchain versions are never deleted or rewritten, so a project pinned to 0.1.0 still builds later. Downloads are verified by SHA-256; signature verification is on the roadmap.
