How a Jax project gets built

Two small pieces: a launcher you install once, and toolchains that arrive when a project asks for them.

The project decides

jax.toml pins the exact toolchain version and is committed with your code.

[project]
jax = "0.1.0"

The launcher fetches

The tiny jax launcher finds that version, downloading and verifying it first if it is missing.

$ jax run
fetching 0.1.0 ... ok

You ship one file

jax build embeds your program in a runtime stub: a standalone executable for each platform.

$ jax build
Built hello (421.9 KiB)

Readable, with the checks you want

Types are inferred inside functions. Enums and match are exhaustive. There is no null: a value that may be missing says so in its type.

src/main.jax
enum Shape {
    Circle(radius: Float)
    Rect(width: Float, height: Float)
    Point
}

fn area(s: Shape) -> Float {
    match s {
        Circle(r) => 3.0 * r * r
        Rect(w, h) => w * h
        Point => 0.0
    }
}

fn main() {
    let big = Shape.Rect(width: 2.0, height: 3.0)
    print("area is {area(big)}")
}
terminal
$ jax new shapes && cd shapes
$ jax run
area is 6.0

# forget a case and the compiler tells you:
error[E0200]: non-exhaustive `match`:
  not covered: Shape.Point
  = help: add the missing cases or
          a wildcard `_` arm

Built to be portable

A project behaves the same on your laptop, a friend's machine and a build server, today and in ten years.

Pinned toolchains

Every project says exactly which Jax it uses: jax = "0.1.0". Ranges are rejected on purpose. Upgrading one project never touches another.

Automatic downloads

Run a project and the launcher fetches any missing toolchain, verifies its SHA-256, installs it atomically and caches it. Versions live side by side.

One-file executables

jax build produces a single file that runs on machines with no Jax installed. Cross-build with --target.

No dependencies, no setup

The whole toolchain is built with zero third-party crates, so bootstrapping is reproducible and works offline.

One command

Create, check, build, run and test with a single jax tool. Errors show the source line and suggest fixes.

Capsules planned

Self-contained project archives with dependencies, tools and even the toolchain inside, so a project can be rebuilt with no network at all.

Status

Jax is at stage 0. The language core, toolchain manager and build pipeline work end to end, and plenty is still ahead.

Works today

  • Functions, structs, enums, pattern matching, optionals, lists and tests
  • The launcher and automatic toolchain install
  • Standalone builds and portable bundles
  • Diagnostics with source excerpts and suggestions

Not yet

  • Generics, traits, closures, Result and ?
  • Async and modules across files
  • The package manager and capsules
  • Native machine code: programs run on a bytecode VM for now

Verify your download

Each launcher has a matching .sha256 file. Compare it with the hash of what you downloaded. The two should be identical.

Windows

(Get-FileHash .\jax.exe -Algorithm SHA256).Hash.ToLower()
Get-Content .\jax.exe.sha256

Linux and macOS

sha256sum jax          # on macOS: shasum -a 256 jax
cat jax.sha256
Read before you run. Piping a script into a shell trusts the server. The scripts are short: install.sh and install.ps1. Both verify the launcher's checksum before installing it. Releases are verified by checksum only; signatures are on the roadmap.

Getting started

Install Jax, make a project, run it and ship it, in about two minutes.

Install

Prefer a direct download? See the download page for every platform.

Linux and macOS

curl -fsSL https://goofymoocow.github.io/jax/install.sh | sh

Windows (PowerShell)

irm https://goofymoocow.github.io/jax/install.ps1 | iex

The installer downloads the launcher (jax, under 1 MB), checks its SHA-256, puts it in ~/.jax/bin (%LOCALAPPDATA%\Jax\bin on Windows), adds that folder to your PATH, and installs the latest toolchain. Open a new terminal afterwards so the PATH change takes effect.

Installer options for Linux and macOS go after sh -s --, for example curl -fsSL https://goofymoocow.github.io/jax/install.sh | sh -s -- --no-toolchain. They are --no-modify-path, --no-toolchain and --version X.Y.Z. On Windows set JAX_NO_MODIFY_PATH, JAX_NO_TOOLCHAIN or JAX_VERSION before running.

Read before you run. Piping a script into a shell trusts the server. The scripts are short: install.sh and install.ps1. Both verify the launcher's checksum before installing it.

Your first project

$ jax new hello
$ cd hello
$ jax run
Hello, Jax!

That created:

hello/
  jax.toml        the manifest: name, version and the exact toolchain
  src/main.jax    your program
  .gitignore
fn main() {
    print("Hello, Jax!")
}

The manifest pins the toolchain the project was created with:

[project]
name = "hello"
version = "0.1.0"
kind = "app"
jax = "0.1.0"   # exact toolchain version; ranges are not allowed

Build and ship

$ jax build
Built build/linux-x64/hello (linux-x64, 421.9 KiB)
$ ./build/linux-x64/hello
Hello, Jax!

The result is one self-contained file. Copy it to another machine of the same platform and it runs without Jax installed.

  • jax build --bundle writes a portable .jxb that any Jax runtime can run.
  • jax build --target windows-x64 cross-builds when the installed toolchain includes that runtime.

Commands

Uninstall

Everything lives in one folder. Delete ~/.jax (or %LOCALAPPDATA%\Jax) and remove the line the installer added to your shell profile (or the folder from your user PATH on Windows).

Building from source

You need Rust 1.75 or newer and nothing else. The workspace has no third-party dependencies.

git clone https://github.com/GoofyMooCow/jax
cd jax
cargo test --workspace      # unit and end-to-end tests
cargo xtask dist            # writes ./dist: launcher + toolchain archive
JAX_DIST_URL=file://$PWD/dist ./dist/bin/linux-x64/jax new hello

Replace linux-x64 with your platform (macos-arm64, windows-x64, ...). On Windows use a file:///C:/path/to/dist URL.

Language tour

Everything on this page runs on the current release.

Variables and constants

const LIMIT = 10           // compile-time constant
let name = "Ada"           // immutable, type inferred (Text)
var visits = 0             // mutable
visits += 1
let ratio: Float = 0.75    // annotations are optional

Built-in types: Int (64-bit), Float, Bool, Text, Unit, List<T>. There are no implicit conversions: use .to_float(), .to_int(), .to_text(). Statements end at a newline; there are no semicolons to forget.

Functions

fn greet(name: Text, excited: Bool = false) -> Text {
    if excited { "Hello, {name}!" } else { "Hello, {name}." }
}

print(greet("Ada", excited: true))   // named arguments, defaults

The last expression is the result. if, match and blocks are expressions. Strings interpolate with {expr}.

Structs and methods

struct User {
    id: Int
    name: Text
    email: Text?
}

impl User {
    fn label(self) -> Text { "{self.name} (id {self.id})" }
    fn rename(mut self, new_name: Text) { self.name = new_name }
}

var u = User(id: 1, name: "Ada", email: none)
u.rename("Ada Lovelace")
let v = u with { email: "ada@example.org" }   // u is unchanged

Structs are values: assigning or passing one never aliases it. Methods take self (read-only) or mut self, and the compiler refuses to modify through a read-only receiver.

Enums and pattern matching

enum Food {
    Fresh(days: Int)
    Pantry
}

fn describe(f: Food) -> Text {
    match f {
        Fresh(d) if d <= 1 => "eat it today"
        Fresh(d) => "good for {d} days"
        Pantry => "keeps forever"
    }
}

match must be exhaustive for enums, Bool and optionals. Patterns support payload bindings, guards, literals, ranges (1..=9), alternatives (A | B) and wildcards.

No null: optionals

let email: Text? = none
let shown = email ?? "no email"          // default
let boss_name = person.boss?.name        // safe access: Text?
if let e = email { print("mail {e}") }   // unwrap safely
match email {
    none => print("nothing")
    some(e) => print(e)
}

A T? cannot be used where a T is required. The compiler tells you to use ??, if let or ! (which panics on none).

Loops and lists

var total = 0
for i in 1..=10 { total += i }            // ranges

var xs: List<Int> = []
xs.push(3); xs.push(4)
for x in xs { total += x }
let third = xs.get(2)                     // Int? (never panics)
loop { break }
while total > 0 { total -= 10 }

Lists are values too (copy on write). xs[i] panics when out of range; xs.get(i) returns an optional.

Tests

test "greeting" {
    assert(greet("Ada") == "Hello, Ada.")
}

Run them with jax test. Tests live next to the code they check.

Built-ins

NameMeaning
print(x)Print an Int, Float, Bool or Text followed by a newline
assert(cond), panic(msg)Abort the program with a stack trace (exit code 101)
text.len(), list.len()Length (characters for text)
list.push(x), list.get(i)Append; checked access
x.to_text(), n.to_float(), f.to_int(), f.sqrt()Conversions and math
Not yet available: generics, trait bounds, closures, Result with ?, async, maps, tuples and multi-file modules. They parse, and the compiler reports E0900 ... is not supported yet rather than miscompiling. See status.

Toolchain & versions

How Jax keeps a project building the same way on every machine, for years.

Two pieces

PieceWhat it is
Launcher (jax)A tiny static program you install once. It reads the project's manifest, makes sure the right toolchain is present, and runs it. It never changes how your code is built.
ToolchainOne directory per Jax version containing the compiler/CLI (bin/jax-driver) and the runtime stubs used for executables. Immutable once installed.

Which version runs?

The launcher picks the first match:

  1. jax +0.1.0 build: an explicit selector
  2. the JAX_TOOLCHAIN environment variable
  3. the jax = "..." pin in the nearest jax.toml (the normal case)
  4. a //! jax 0.1.0 comment in the first lines of a single .jax file
  5. your default toolchain, else the newest installed, else the newest available

If the chosen version is missing it is downloaded, its SHA-256 is verified against the release manifest, and it is unpacked and moved into place atomically, so an interrupted download never leaves a half-installed toolchain. Concurrent runs coordinate with a lock.

Managing toolchains

jax toolchain list              # installed versions (* = default)
jax toolchain install 0.1.0     # add --set-default to make it the default
jax toolchain remove 0.1.0
jax toolchain default 0.1.0
jax toolchain which             # the driver that would run here
jax toolchain latest            # newest version the server offers
jax toolchain prune [--yes]     # remove versions nothing needs (dry run without --yes)

Where things live

~/.jax/                       # %LOCALAPPDATA%\Jax on Windows; override with JAX_HOME
  bin/jax                     # the launcher
  toolchains/0.1.0/           # one folder per version
    bin/jax-driver
    runtimes/linux-x64/jax-rt
  config.toml                 # preferences; never affects build output
  tmp/  locks/                # scratch space

Environment variables

VariableMeaning
JAX_HOMEWhere Jax keeps toolchains and config
JAX_DIST_URLWhere toolchains are downloaded from (https://, or file:// for a local folder)
JAX_OFFLINE=1Never touch the network; fail with a clear message if something is missing
JAX_TOOLCHAINForce a toolchain version
JAX_VERBOSE=1Say which toolchain was chosen and why

Hosting your own mirror

Distribution is just static files. Any web server, object store or shared folder works:

latest.txt
toolchains/0.1.0/manifest.toml                          # sha256 for every platform
toolchains/0.1.0/jax-toolchain-0.1.0-linux-x64.tar
bin/linux-x64/jax   and   jax.sha256                    # the launcher, used by the installers

Point JAX_DIST_URL (or dist_url in config.toml) at it. The default is https://goofymoocow.github.io/jax/dist. For an air-gapped machine, copy a dist folder over and use a file:// URL together with JAX_OFFLINE=1.

Releases are permanent

Published toolchain versions are never deleted or rewritten, so a project pinned to 0.1.0 still builds later. Downloads are verified by SHA-256; signature verification is on the roadmap.

Status & roadmap

Jax is at stage 0 (0.1.0). This page says plainly what exists.

Works today

  • Launcher and toolchain manager: pinned versions, automatic download, SHA-256 verification, atomic install, several versions side by side, offline mode, mirrors.
  • Manifest: jax.toml with strict validation (exact versions only, known targets, dependency tables) and a deterministic jax.lock format.
  • Language core: functions with named and default arguments, let/var/const, structs and methods (mut self, with), enums with payloads, exhaustive match, optionals, lists, loops, tests.
  • Diagnostics: source excerpts, error codes, "did you mean" suggestions.
  • Builds: standalone executables, portable .jxb bundles, cross-target builds when the runtime is present.
  • Zero third-party dependencies in the whole toolchain.

Parsed, but not implemented yet

The compiler reports E0900 for these instead of guessing:

  • Generics and trait bounds (traits parse; impl Trait for Type adds methods without checking the trait)
  • Closures and function values
  • Result and the ? operator; main returning a value
  • async / await and concurrency primitives
  • Map, Set, tuples, sized integer types
  • Multiple files and modules (use beyond std)

Planned tooling

  • jax fmt, jax lint, jax doc, jax bench, language server
  • Package manager and registry: add, vendor, publish, reproducible resolution
  • Capsules (.jcap) and jax dist: sealed archives that rebuild with no network
  • Signed releases

Known differences from the long-term design

Programs run on a bytecode VM today, not as native machine code. A built executable is the Jax runtime plus your compiled program in one file. It is portable and self-contained, but slower than the native code Jax is meant to produce. The bytecode format is the seam where native backends will plug in.
  • The standard library is small: no files, networking or standard input yet.
  • HTTPS downloads use the system curl (present on Windows 10+, macOS and mainstream Linux).
  • Releases are verified by checksum only; signatures come later.
  • The download site is currently GitHub Pages and will move to a dedicated domain. Installed launchers keep working; see the notes in the repository.
